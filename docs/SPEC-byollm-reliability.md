# Надёжность BYOLLM и настроек

Дополняет [SPEC-primitive-setup.md](./SPEC-primitive-setup.md) и частично заменяет требования обработки ошибок из [SPEC-llm-settings-universal.md](./SPEC-llm-settings-universal.md).

## Проблема

OpenAI-compatible подключение работает в happy path, но ошибки запроса скрываются UI, оборванный стрим попадает в историю, а сохранение настроек выполняется без ожидания и подавляет ошибки. Навигация из меню в setup также теряет предыдущий экран.

## Текущее состояние

- `src/ui/BarScreen.tsx:85` подавляет rejection от `runTurn`.
- `src/agent/loop.ts:163` финализирует частичный стрим при ошибке.
- `src/state/app.ts:35` запускает сохранение без ожидания.
- `src/bootstrap.ts:21` повторно сохраняет только что загруженные настройки.
- `src/persistence.ts:62` распознаёт новый формат только по endpoint/token.
- `src/persistence.ts:85` подавляет ошибки записи и не гарантирует `0o600` для существующего файла.
- `src/agent/providers/openai.ts:88` отдельно и неполно классифицирует SSE-ошибки.
- `src/ui/SetupScreen.tsx:64` всегда возвращает из setup в bar.

## Дизайн

1. `savePreferences` сериализует атомарные записи через временный файл и `rename`, не подавляет ошибки и гарантирует режим `0o600`.
2. `useAppStore.setPrefs` возвращает `Promise<void>` и обновляет память только после записи. `hydratePrefs` обновляет память без записи при bootstrap.
3. Setup показывает процесс и ошибку сохранения, блокирует повторный submit и использует `back()` при отмене.
4. Загрузка сохраняет все валидные частичные поля и принимает `extraHeaders` только со строковыми значениями.
5. Общий классификатор обрабатывает HTTP и SSE status/code, включая числовые строки.
6. Ошибка хода удаляет незавершённый стрим. Для технической ошибки остаётся одна реплика персонажа, а UI добавляет безопасное системное сообщение. Abort не создаёт сообщений.
7. Usage остаётся best effort: `stream_options.include_usage` не отправляется безусловно, поскольку часть OpenAI-compatible endpoint отклоняет это поле.

## Тесты

- Ошибки, частичные значения, атомарность и порядок записей preferences.
- Bootstrap без побочного сохранения.
- Ошибка сохранения и возврат setup в предыдущий экран.
- SSE 401/403/429/5xx и числовые строки.
- Оборванный стрим, abort и безопасное сообщение в UI boundary.

## Критерии готовности

- Пользователь видит причину типовой ошибки подключения без утечки секретов.
- Частичный ответ не попадает в историю после ошибки.
- Setup не закрывается до успешного сохранения.
- Последняя вызванная запись preferences побеждает и создаёт файл с `0o600`.
- `npm run typecheck`, `npm test` и `npm run build` проходят.

## Оценка

Средняя: изменения нескольких слоёв с регрессионными тестами, без изменения публичного формата preferences.
