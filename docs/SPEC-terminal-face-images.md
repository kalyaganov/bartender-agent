# Изображения лица Виктора в терминале

## Проблема

`src/ui/Face.tsx:10-48` всегда выводит Unicode/ASCII-лицо из `src/ui/faces.ts:62-73`. Пользователь предоставил один PNG-лист с десятью подписанными портретами Виктора — по одному для каждого значения `Mood` из `src/agent/schemas.ts:3-14` — и просит показывать головы изображениями, когда терминал это умеет.

## Текущее состояние

- `BarScreen` выводит `Face` в центре экрана (`src/ui/BarScreen.tsx:120-122`).
- ASCII-рендерер меняет строку глаз при моргании и сдвигает строку бровей при смене настроения (`src/ui/Face.tsx:15-46`).
- Сборка создаёт только `dist/index.js` (`package.json:42-48`), а пакет публикует `dist` и служебные файлы (`package.json:33-38`).

## Дизайн

1. Вырезать из листа десять PNG без плашек-подписей: по одному файлу в `assets/faces/` для каждого `Mood`.
2. Добавить модуль терминальной графики. Он определяет Kitty/Ghostty по `KITTY_WINDOW_ID` или `TERM_PROGRAM=ghostty`, а iTerm2 и WezTerm — по `TERM_PROGRAM`/`LC_TERMINAL`. Неподдерживаемые терминалы, `tmux`, отсутствие TTY и тестовая среда возвращают `null`.
3. Модуль читает нужный PNG из каталога пакета, кодирует его в base64 и формирует escape-последовательность Kitty либо iTerm2. Перед каждой заменой удаляются предыдущие изображения: Kitty получает команду удаления graphics-слоя, а для iTerm2 очищается прямоугольник строк лица. Затем новое изображение не передвигает курсор; Ink резервирует под него 14 строк и продолжает управлять разметкой.
4. `Face` выбирает графический рендерер при доступности протокола, иначе без изменений использует ASCII-рендерер с морганием и подёргиванием бровей. При смене настроения и размонтировании компонента (переходе в настройки, меню или подтверждение выхода) cleanup удаляет graphics-слой. PNG-вариант статичен: для каждого настроения используется предоставленная готовая иллюстрация.
5. Каталог `assets` включается в npm-пакет. В dev-режиме и после сборки путь к ресурсам находится относительно файла исполняемого модуля.

## Затронутые файлы

- `assets/faces/*.png` — подготовленные портреты.
- `src/ui/terminalImage.ts` — capability detection, поиск ресурсов и escape-последовательности.
- `src/ui/Face.tsx` — выбор PNG либо ASCII.
- `src/tests/terminalImage.test.ts` — выбор протокола, fallback, поиск имени файла и последовательности.
- `package.json` — публикация ресурсов.
- `README.md` — описание PNG-портретов и fallback.

## Тесты

- Kitty, Ghostty, iTerm2 и WezTerm выбирают правильный протокол.
- Не-TTY, `tmux` и неизвестный терминал используют ASCII fallback.
- Escape-последовательность содержит выбранную геометрию и PNG payload.
- При смене настроения и уходе с BarScreen удаляется предыдущее изображение.
- Перед завершением: `npm run typecheck` и `npm test`.
