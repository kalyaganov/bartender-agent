# Надёжность и диагностика хода агента

Дополняет [SPEC-byollm-reliability.md](./SPEC-byollm-reliability.md).

## Проблема

Цикл агента принимает последний из нескольких tool-call без проверки, оставляет завершённый abort-контроллер в модуле и не позволяет отменить паузу между повторными запросами. При одновременном content и `bartender_action.reply` источник видимой реплики не определён. В `/state` нет безопасной диагностики результата хода, а модель может резко занизить оценку опьянения относительно предыдущего хода.

## Текущее состояние

- `src/agent/loop.ts:25-30` хранит один контроллер попытки.
- `src/agent/loop.ts:38-65` не получает сигнал отмены всего хода.
- `src/agent/loop.ts:124-129` перезаписывает аргументы каждого `tool-call`.
- `src/agent/loop.ts:134-158` применяет действие и выбирает текст без проверки протокола нескольких вызовов.
- `src/state/store.ts:21-46` не хранит итог или диагностику хода.
- `src/state/reducer.ts:47-51` принимает новую модельную оценку без ограничения скорости снижения.

## Дизайн

1. Один ход получает родительский `AbortController`; каждая попытка получает дочерний. Отмена прерывает стрим и backoff. В `finally` активный контроллер очищается.
2. Все tool-call накапливаются до finish. Действие допустимо только при единственном валидном вызове `bartender_action`. Неожиданные инструменты не исполняются и отражаются в диагностике.
3. Для валидного действия `reply` — единственный источник финальной реплики. При отсутствии или невалидности действия показывается content, а при его отсутствии — fallback.
4. Store хранит безопасный `lastTurnStatus`: число попыток, результат проверки инструментов, их число, источник реплики и тип ошибки. `/state` выводит эти поля без сырых ошибок и секретов.
5. При ненулевом алкогольном прокси оценка опьянения не может уменьшаться более чем на настроенный шаг за ход. Порог forced refusal в редюсере остаётся окончательным.
6. `executeTurn` разделяется на подготовку, сбор стрима, разрешение ответа, commit и обработку ошибки внутри модуля без изменения публичного API.

## Тесты

- Один, несколько, чужой и невалидный tool-call.
- Приоритет `tool.reply` над content и content без action.
- Отмена во время стрима и во время retry-backoff.
- Очистка активного контроллера и отсутствие двойного применения напитка после retry.
- Диагностика успеха и ошибки без технического текста провайдера.
- Консервативное снижение оценки при уже выпитом алкоголе.

## Критерии готовности

- Игровое действие не применяется из неоднозначного или невалидного tool-call.
- `cancelCurrentTurn()` не допускает следующую retry-попытку.
- Итоговая реплика и `/state` детерминированы для каждого результата протокола.
- `npm run typecheck`, `npm test` и `npm run build` проходят.

## Оценка

Средняя: изменения локальны для цикла, store и чистого редюсера, но требуют асинхронных регрессионных тестов.
