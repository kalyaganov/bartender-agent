# ADR-0006: Порог опьянения ≥7 — жёсткий отказ

- **Status:** Accepted
- **Date:** 2026-10-17
- **Deciders:** Alexey Kalyaganov

## Context

Игровая механика: бармен оценивает опьянение гостя и при достижении определённого уровня отказывает в обслуживании. Это ключевая фича игры — она создаёт напряжение и реалистичность.

Проблема: как реализовать порог отказа, если модель может вернуть `pour_drink` даже когда гость уже пьян?

## Decision

**Форсированный отказ в reducer** (`src/state/reducer.ts`):

```typescript
const tooDrunk = newDisplay >= config.drunkenness.refuseThreshold; // 7

if (drink.alcoholic && (tooDrunk || state.phase === "cutOff")) {
  // Forced refuse: напиток не записывается, таб и bacProxy не растут
  next.mood = "firm";
  next.bacProxy = state.bacProxy;
  next.phase = "cutOff";
}
```

**Ключевые решения:**

1. **Порог = 7** (`config.drunkenness.refuseThreshold`) — окончательный, не поддаваться уговорам «ещё одну»
2. **Форсированный отказ в reducer** — даже если модель вернула `pour_drink`, reducer не добавляет напиток в served/tab
3. **Формула опьянения** (`src/state/drunkenness.ts`):
   - `drunkenness = 0.8 * perceivedScore + 0.4 * bacProxy`
   - `perceivedScore` — оценка моделью по реплике гостя (0-10)
   - `bacProxy` — сумма алкогольных единиц выпитых напитков
4. **Метаболизм** — `bacProxy` уменьшается на 0.05/минуту
5. **Фазы:** `open` → `cutOff` (при достижении порога) → `leaving` (при call_taxi) → `closed`

## Consequences

**Позитивные:**
- Жёсткое правило игры — пользователь знает, что после 7 не наливают
- Реалистичность — бармен отказывает пьяному гостю
- Безопасность — игра не поощряет чрезмерное употребление
- Легко настроить порог — изменить `config.drunkenness.refuseThreshold`

**Негативные:**
- Модель может пытаться обойти правило — но reducer это блокирует
- Порог может быть слишком строгим или слишком мягким — нужна балансировка

## Alternatives Considered

1. **Только system prompt** — просить модель не наливать при высоком опьянении. Отклонено: модель может не послушаться, нет гарантии.
2. **Порог в UI** — скрывать кнопку заказа. Отклонено: пользователь может вводить текст, не только кнопки.
3. **Мягкий порог** — предупреждение, но не отказ. Отклонено: разрушает механику игры.
