# ADR-0007: BYOK — без env API keys

- **Status:** Accepted
- **Date:** 2026-10-17
- **Deciders:** Alexey Kalyaganov

## Context

Проект использует LLM-провайдеров, которые требуют API-ключи. Изначально ключи могли задаваться через переменные окружения.

Проблемы env-подхода:
- Пользователь должен настроить env перед запуском
- Ключи могут попасть в логи или системные переменные
- Несколько пользователей на одной машине — конфликт ключей
- Сложно переключать провайдеры

## Decision

**BYOK (Bring Your Own Key)** — пользователь сам вводит API-ключ и endpoint в настройках приложения.

**Ключевые решения:**

1. **Хранение в `~/.bartender-agent/preferences.json`** (`src/persistence.ts`):
   - `{endpoint, token, model, thinking, extraHeaders}`
   - Права доступа `0o600` (только владелец)
   - Атомарная запись через temp-файл + rename

2. **Загрузка при старте** (`src/bootstrap.ts`):
   - `loadPreferences()` → `resolveInitialScreen()`
   - Если настроено → экран бара
   - Если нет → экран настройки

3. **Мягкая миграция** из легаси-формата:
   - Старый каталог `~/.homeagent/` → `~/.bartender-agent/`
   - Легаси-формат `credentials.custom` → плоский формат

4. **Никаких env API keys** — код не читает переменные окружения для ключей

## Consequences

**Позитивные:**
- Пользователь полностью контролирует свои ключи
- Проще переключать провайдеров — изменить настройки в UI
- Безопасность — ключи в файле с правами 0o600, не в env
- Несколько пользователей — у каждого свои настройки

**Негативные:**
- Пользователь должен сам ввести ключ — чуть сложнее при первом запуске
- Ключ хранится в открытом виде в файле (но с ограниченными правами)

## Alternatives Considered

1. **Env-переменные** — исходный подход. Отклонено: неудобно для пользователя, проблемы с безопасностью.
2. **Ключ в коде** — хардкод. Отклонено: небезопасно, невозможно обновить.
3. **Отдельный файл для ключа** — `~/.bartender-agent/key`. Отклонено: усложняет структуру, один файл проще.
