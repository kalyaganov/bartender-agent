# ADR-0005: Tool calling — bartender_action каждый ход

- **Status:** Accepted
- **Date:** 2026-10-17
- **Deciders:** Alexey Kalyaganov

## Context

Бармен должен не только говорить, но и **действовать**: наливать напитки, менять настроение, оценивать опьянение, отказывать в обслуживании. Это структурированные данные, которые нельзя передать через свободный текст реплики.

Проблема: как заставить модель вызывать tool call каждый ход, если разные провайдеры по-разному поддерживают `tool_choice`?

## Decision

**Инструмент `bartender_action`** (`src/agent/tools.ts`):

```typescript
{
  reply: string;              // Разговорная реплика (обязательно)
  mood: Mood;                 // Настроение (10 вариантов)
  action: Action;             // Действие (7 вариантов)
  drink?: Drink;              // Напиток (при pour_drink/serve_water)
  drunkennessAssessment: {    // Оценка опьянения гостя
    score: number;            // 0-10
    cues: string[];           // Что заметил
  };
}
```

**Ключевые решения:**

1. **Модель обязана вызывать `bartender_action` каждый ход** — предписано в system prompt
2. **`tool_choice` НЕ форсируется программно** — провайдеры расходятся в поддержке:
   - ZAI режектит named tool_choice
   - DeepSeek-thinking режектит `required`
3. **Реплика — в поле `reply` внутри tool call** (для reasoning-моделей) ИЛИ в content-стриме (для обычных). Loop обрабатывает оба случая.
4. **Zod-валидация** (`src/agent/schemas.ts`) — `BartenderAction.safeParse()` проверяет структуру

## Consequences

**Позитивные:**
- Чёткое разделение: реплика (текст) vs действие (структурированные данные)
- Модель может вызвать несколько tool calls за ход — loop обрабатывает это
- Валидация через zod — защита от некорректных ответов модели
- Реплика доступна и в reasoning-моделях (через `reply`), и в обычных (через content)

**Негативные:**
- Модель может не вызвать tool call — loop обрабатывает это как `missing` и делает retry
- Сложнее отлаживать — нужно проверять и текст, и tool call

## Alternatives Considered

1. **Только свободный текст** — без tool calls. Отклонено: невозможно структурировать действия (налить, отказать, оценить опьянение).
2. **tool_choice: "required"** — форсировать вызов. Отклонено: не все провайдеры поддерживают, модель может вернуть пустой вызов.
3. **Несколько инструментов** — отдельный tool для каждого действия. Отклонено: усложняет system prompt, модель может вызвать не тот tool.
