# ADR-0003: Двойной Zustand store + чистый Reducer

- **Status:** Accepted
- **Date:** 2026-10-17
- **Deciders:** Alexey Kalyaganov

## Context

Игровое приложение имеет два типа состояния:
1. **Сессионное** — состояние текущего вечера в баре: диалог, настроение, опьянение, счёт, фаза. Сбрасывается между сессиями.
2. **Прикладное** — настройки приложения: текущий экран, предпочтения провайдера. Сохраняется между сессиями.

Нужно разделить эти типы состояния и обеспечить тестируемость игровой логики.

## Decision

**Два Zustand store:**

1. **`store.ts`** (session store) — сессионное состояние:
   - `GameState` (mood, phase, perceivedScore, bacProxy, drunkenness, served, tab)
   - UI-состояние (lines, streamingText, busy, pouring)
   - Сбрасывается при `reset()`

2. **`app.ts`** (app store) — прикладное состояние:
   - `screen` — текущий экран (bar, setup, menu, exit-confirm)
   - `prefs` — предпочтения провайдера
   - Не сбрасывается между сессиями

**Чистый Reducer:**

`applyAction(state, action, now)` в `src/state/reducer.ts` — чистая функция, тестируемая отдельно:
- Применяет действие бармена к игровому состоянию
- Вычисляет новую оценку опьянения
- Форсирует отказ при достижении порога (≥7)
- Управляет фазами (open → cutOff → leaving → closed)

**Side effects в store.ts:**
- Анимация наливания (только если напиток реально подан)
- Тик метаболизма
- Стриминг

## Consequences

**Позитивные:**
- Чёткое разделение: сессионное vs прикладное состояние
- Игровая логика тестируется без UI и сайд-эффектов
- Легко добавить новые действия — расширить reducer
- Предсказуемость: одинаковый вход → одинаковый выход

**Негативные:**
- Некоторое дублирование: reducer вычисляет состояние, store добавляет сайд-эффекты
- Нужно следить за тем, чтобы reducer оставался чистым

## Alternatives Considered

1. **Один store для всего** — и сессионное, и прикладное состояние вместе. Отклонено: сложно сбрасывать сессию, нечёткое разделение ответственности.
2. **Reducer для всего состояния** — включая прикладное. Отклонено: усложняет reducer, смешивает игровую логику с настройками приложения.
3. **Контекст + useReducer** — классический React-подход. Отклонено: Zustand проще для TUI-приложения, не требует Provider.
