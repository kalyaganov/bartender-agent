# Сохранение ввода при навигации по /командам

## Проблема

В основном экране после ввода `/` появляется попап команд. Нажатие стрелки вниз перемещает выделение, но текст в `InputBox` визуально сбрасывается. Пользователь теряет введённый префикс и не может предсказуемо выбрать команду.

## Текущее состояние

- `src/ui/BarScreen.tsx` хранит `inputValue` и выбранный индекс попапа.
- `src/ui/BarScreen.tsx` очищает любое непустое значение при `key.escape`.
- Escape-последовательность стрелки может быть обработана как Escape, поэтому `/` очищается до обработки навигации.
- Для полного сценария `BarScreen` нет UI-теста, проверяющего сохранение значения после навигации.

## Дизайн

1. `BarScreen` использует Escape только для перехода к подтверждению выхода при пустой строке. При непустом вводе он не очищает строку: Escape может быть частью последовательности стрелки для попапа.
2. ↑/↓ меняют только выбранный пункт и не меняют `inputValue`.
3. Tab подставляет выбранную команду по существующей логике `BarScreen`.
4. Добавляются UI-регрессии полного сценария: `/` → ↓ сохраняет `/` и меняет выделение; отдельный Escape при открытом попапе также не очищает `/`.

## Затронутые файлы

- `src/ui/BarScreen.tsx`
- `src/tests/ui.test.tsx`

## Критерии готовности

- Стрелка вниз не очищает строку ввода при открытом попапе.
- Навигация и Tab-подстановка продолжают работать.
- `npm run typecheck` и `npm test` проходят.
