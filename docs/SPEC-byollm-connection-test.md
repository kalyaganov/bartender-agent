# Проверка подключения BYOLLM и подсказки настройки

Дополняет [SPEC-primitive-setup.md](./SPEC-primitive-setup.md) и [SPEC-byollm-reliability.md](./SPEC-byollm-reliability.md).

## Проблема

Форма BYOLLM принимает endpoint, token, model и Thinking, но пользователь не может проверить введённые значения до сохранения и запуска игрового хода. Неясно, какой URL ожидается: часть пользователей вставит полный `/chat/completions`, хотя OpenAI SDK ожидает базовый URL. Также неочевидно, нужен ли Thinking конкретной модели.

## Текущее состояние

- `src/ui/SetupScreen.tsx` сохраняет настройки без сетевой проверки.
- `src/agent/loop.ts` создаёт `OpenAIProvider` только при первом игровом ходе.
- `src/agent/providers/openai.ts` работает через OpenAI Chat Completions API и стриминг.
- `thinking` меняет тело запроса: добавляет `reasoning`, заменяет `max_tokens` на `max_completion_tokens` и убирает `temperature`.

## Дизайн

1. В форме появляется отдельный пункт «Проверить подключение» перед сохранением. Он использует текущие значения формы, ничего не записывает на диск и блокирует повторный ввод на время запроса.
2. Проверка создаёт обычный провайдер и выполняет короткий streaming-запрос через тот же Chat Completions путь, что и игровой ход. Запрос содержит настоящий `bartender_action` и тот же набор generation-параметров, включая Thinking.
3. Результат разделяется на три состояния:
   - соединение, streaming и tool calling работают;
   - Chat Completions и streaming работают, но модель не вызвала инструмент — это предупреждение, поскольку Виктору нужна модель с tool calling;
   - ошибка соединения — понятное безопасное сообщение без текста провайдера и секретов.
4. Подсказки у полей поясняют, что endpoint — базовый URL OpenAI-compatible API, обычно оканчивается на `/v1`, а не `/chat/completions`; model — точный ID от провайдера; token не сохраняется проверкой.
5. Thinking остаётся пользовательской расширенной опцией, по умолчанию выключенной. Автоопределение не вводится: формат reasoning и допустимые параметры различаются между endpoint. Подсказка объясняет, что большинство моделей не требует включения, а включать его стоит только если провайдер документирует OpenRouter-совместимый reasoning; проверка позволяет сразу проверить выбранный режим.

## Затронутые файлы

- `src/agent/connection.ts` — короткая проверка совместимости Chat Completions/tool calling.
- `src/ui/SetupScreen.tsx` — пункт проверки, статусы и подсказки.
- `src/tests/connection.test.ts` — успешная проверка и предупреждение без tool call.
- `src/tests/ui-setup.test.tsx` — навигация, результат проверки и отсутствие сохранения.

## Тесты

- Проверочный запрос использует `BARTENDER_TOOL`, streaming и generation-параметры с Thinking и без него.
- Валидный `bartender_action` даёт успешный результат; отсутствие или невалидность инструмента даёт предупреждение.
- Ошибка провайдера пробрасывается в UI и показывается без сырого текста.
- Проверка не вызывает `setPrefs`/`savePreferences`.

## Критерии готовности

- До сохранения пользователь видит результат реального запроса к указанному endpoint.
- Подсказка предотвращает передачу полного URL `/chat/completions` вместо base URL.
- Thinking остаётся необязательным и безопасно выключен по умолчанию.
- `npm run typecheck` и `npm test` проходят.
